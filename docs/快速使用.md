# AutoMM 快速使用

2026-09-10：DeepSeek 官方 API 已配置，真实调用及 AutoMM provider JSON schema 校验通过。当前模型 deepseek-v4-flash，推理强度 high。整题研究还没有运行。

## 放入题目

在工作区 `AutoMM` 子目录中：

- `request/problem.md`：完整题面。当前仍是上游 2024 C 题示例，必须替换。
- `request/attachments/`：官方题目 PDF、说明等附件。
- `data/`：数据表及输出模板，保留原始文件。

## 初始化并运行

打开 PowerShell，进入工作区：

```powershell
cd 'F:\AcademicHub\000资料相关\数模\26国赛'
.\automm.ps1 check
```

放好题目后初始化。下面只是“2026 C 题、3 个小问”的示例，按实际修改 ID 和小问数；每道题仅首次初始化，不拿初始化当恢复命令：

```powershell
.\AutoMM\.venv\Scripts\python.exe .\AutoMM\scripts\harness.py init-problem --problem-id cumcm2026_c --questions 3
.\automm.ps1 once
```

`once` 只推进一个动作。确认单步结果正常后开启持续运行：

```powershell
.\automm.ps1 daemon
```

保持该终端打开。持续运行会调用付费 API，并在本地创建计算任务。第一次遇到 blocked/失败，应先检查原因，不盲目重复启动。

## 查看进度与控制

[仪表盘](http://127.0.0.1:8765/) 是只读监测台，打开它不等于启动建模。若尚未运行，在另一终端执行：

```powershell
.\automm.ps1 monitor
```

当前已有监测服务时直接打开网页即可。暂停、恢复、停止调度也从另一个终端运行：

```powershell
.\automm.ps1 pause
.\automm.ps1 resume
.\automm.ps1 stop
```

上述三个命令是按需要分别执行，不要整段连跑。控制在编排边界生效，不承诺立即中断正在执行的模型调用或计算。STOP 会取消排队计算，不能等同于杀死全部进程；关闭 daemon 终端前宜先暂停并检查运行任务。正常暂停后恢复用 resume；发生 invariant、凭据或模型错误时，应先查日志，不能用恢复命令跳过故障。

## 它会输出什么

按小问依次推进读题、文献、假设、公式、实现、计算、校验和可视化等阶段。过程资产在 `AutoMM/problems/`，动作证据在 `AutoMM/runtime/actions/`，daemon 日志在 `AutoMM/runtime/daemon/daemon.log`。最终总结预期为 `AutoMM/reports/final_summary.md`。

AutoMM 提供研究材料与结果，当前版本不自动交付参赛论文。每阶段结果需要团队核验；完整研究也不能仅凭进程退出或某个 Markdown 出现就宣布成功。

你也可以直接告诉 Codex：题面和数据放好了、题号和小问数是什么，让它按上述流程初始化、单步验收和调度。
