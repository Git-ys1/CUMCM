## 三、新审阅文档应该放哪？

**放 `02_版本审阅归档/<版本号>/`**，理由：

1. 与论文版本绑定，检索时"按版本查审阅"最直接；
2. 与 `00_长期审阅标准` 分离——标准是不变的尺子，审阅是量出来的数，混在一起会分不清；
3. 版本迭代后可整体标记"过期"，不会污染当前工作集。

**同时**在该版本交付目录（如 `论文迭代/C题论文V5.2_MathModel交付/说明/`）保留一份副本，便于跟随交付包流转。

### 本轮实际安排了什么

| 份数 | 来源 | 处理 |
|---|---|---|
| 3 份 | WorkBuddy（审查①②③） | 原在 `V5/`，已由用户独立到 **`V5.2/`** |
| 1 份 | **用户审阅建议**（标题/字体/空白页/后段语句） | 由 WorkBuddy 实测核查后写成**审查④**，归 `V5.2/` |
| 1 份 | MathModel `review-V5.2.md` | 从 `Codex-MathModel/Review/` 复制一份到 `V5.2/` |

> 汇总结论统一由**审查④**承担，它是五源的收敛点，读它即可，不必逐份翻。

## 四、状态标记约定

每篇审阅文档在产出时须在开头标注状态：

| 标记 | 含义 |
|---|---|
| 🟢 **现行** | 当前版本的有效审阅，须据此修改 |
| 🟡 **部分过期** | 部分条目已被后续版本解决 |
| ⚪ **过期** | 全部要求已被满足，仅作追溯留档 |

被标记为"过期"的文档**不删除**，改名前缀为 `【过期】`，保留决策链完整性。
