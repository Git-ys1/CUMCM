# 项目长期约定（C 题 · 2026 高教社杯国赛 · WorkBuddy 侧）

> 最后更新：2026-09-12

## 一、分工与工作流（2026-09-12 起生效，重要）

- **论文核心撰稿由人工（团队）负责**：每个 `.tex` 文件由团队自己编辑，**最终由用户本人编译**。
- **agent（WorkBuddy / MathModel）此后只做**：建模、绘图、求解、重跑、生成数值与图表、以及**审阅/审计**。
- **agent 不再撰稿**：用户判断——agent 的文字表达能力不及 chat 级，论文写作上再多 skill 也无法弥补。
- **审阅文档的建议**：保留为**最终审阅入库要求**（验收清单），不必逐条由 agent 落地到论文。
- **交接顺序**：agent 先跑出数值基线（numbers.tex / generated/ / result*.xlsx）→ 人工编辑 TeX → 用户编译 → 放回工程由 agent 复核。
- **发布是链路的一环，产出即发布**：用户工作流是「agent 产出文档 → 同步到 `_publish/repo` → 推送 GitHub → 网页端 GPT 读 raw 链接」。**agent 产出审查/建议文档后必须主动发布，不得等用户来问**。发布后给出 `https://raw.githubusercontent.com/Git-ys1/CUMCM/main/<路径>` 形式链接供网页端直接抓取。
- 参考范文（如全糖奶茶屋）**只学写法与格式**，不得复制文字/公式/图表（版权+查重红线）。

## 二、Q3 结算口径（2026-09-12 拍板，长期有效）

- 主结算 = **差额部分结算**（不再使用 additive / replacement 说法）：
  `C_t = p_t·min(Gᵖ,Gᵃ) + 0.5p_t(Gᵖ−Gᵃ)⁺ + 1.5p_t(Gᵃ−Gᵖ)⁺`，不足再加 `5p_t·E_t`
- 判例：5000→4000 = 4500p（**非** 5500p）；4000→5000 = 5500p。
- 两套解释**仅在向下调整时分歧**；差额结算更符合题面"部分/超出部分/违约电价"的措辞与经济含义。
- 切换后的 Q3 主结果：**13 727 998.70 元**（原 additive 为 13 917 403.19）。Q1/Q2/Q4-2 不受影响。

- ✅ **2026-09-12 晚：该切换已在 V5.2 全面落地**。实测 `\QthreeSthree = 13 727 998.70`（差额）；Q3 四节点 S0 15 731 164.40 / S1 14 505 850.38 / S2 14 353 879.08 / S3 13 727 998.70；Q4-3 = 14 387 959.47（原 14 589 632.38）；新增宏 `\QtwoPerfectInfo` = 13 275 988.13、`\QthreeSumTotal` = 13 917 403.19 均已定义。

## 三、写作与排版硬性规范（用户亲述，务必遵守）

1. **问题重述 / 分问**：用「**问题一：**」（中文数字 + 全角冒号）接正文，**首行缩进 2 字符、换行顶格**；禁用 `enumerate` 悬挂缩进、禁用"问题 1."。
2. **顶格/缩进规则**："顶格就需要有标题，没有标题的就首行缩进"——禁"顶格无标题"或"有标题却缩进"。
3. **版本号纪律**：论文、代码、支撑材料一律**不得出现 V3/V4 等内部版本号**（仅团队内部区分稿件用）。
4. **措辞去 AI 味**：如"因而直接代入附件 4 是主口径""附件 4 直用（主结果）："这类生硬短句需改为自然书面语。
5. **"口径"一词大幅降频**（目标 ≤3 次）：结算口径→结算规则/计费方式；效率口径→效率定义/效率取值；主口径→主方案/主模型；信息口径→可用信息范围/信息条件；表格标签"口径A/B"→"定义 A/B"。
6. **正文禁工程术语**：mutation、legacy、消融（改"对照实验"）、口径锁定等。
7. **禁用"不是……而是……"式辩论句**（用户 2026-09-12 点名，指导书 §1.5 亦有明文）。改法：**直接陈述正面事实，删掉被否定的那一半**。V5 曾达 19 处"不是"、13 处对照句式。
8. **禁用"母线侧""母线平衡"**（用户点名；指导书 §2.1：原题无"母线"一词）。改为**微网能量平衡 / 能量平衡式 / 流入（流出）储能的电量**；确需公共节点概念时先写"将外网、光伏、负载和储能连接的公共电能交换点视为同一节点"。
9. **过渡词降频**：因此/同时/进一步 需控制在 ~22/~19/~8 以内；"在此基础上""综上所述""值得注意的是"必须 0 次。

## 四、数值与生成物纪律

- **所有结果数字由 `numbers.tex` 宏注入**（`solve/report.py` 生成），**禁止手改**。

- 每次改动后需重跑全部测试并重编译核页。

## 八、git 操作教训（本项目专用）

- **`git rm -r` 有级联误删风险**：曾因 `git rm -r MathModel/delivery_v4` 导致整个 `MathModel/` 从工作树消失。删除后必须立即 `ls` 复查；误删用源侧 `cp -ru` 恢复。
- **中文路径会被 git 转成八进制转义**：`ls-tree`/`diff --name-only` 直接 grep 中文得到 0 是**假阴性**。核对时用 `core.quotepath=false`。
- **push 后 `origin/main` 本地 ref 可能未刷新**：核对云端内容改用 `HEAD`。
- **发布惯例**：定向 `git add`（绝不 `-A`）→ commit → `git pull --rebase origin main` → push。排除 `MathModel/outputs/`（346MB）、构建日志、`__pycache__`。
- **版权红线**：不发布 `数模加油站/`（注意：其"蒋老师"3 个 PDF 已在历史提交 a908d6b/dba85a9 中，早于我介入，需用户决定）、不发布 17 篇国奖获奖论文原件。`全糖奶茶屋/论文节选图片集*.docx`（22MB 第三方截图）暂未入库，待用户确认。
